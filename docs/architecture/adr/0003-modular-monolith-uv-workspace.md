# ADR-0003: A modular monolith in a uv workspace of namespace packages

- Status: Accepted (A0 checkpoint, 7 November 2026)
- Handoff §1: Architecture

## Context

v0 is one package `optlab/` of about 30,000 lines of Python (9,300 of tests), with a CUDA engine beside it, a desk in
`optlab/app`, and boundaries that are only conventions. The import graph has two cycles (ADR-0004). One person
maintains it, on one machine: microservices would multiply deployments, network calls and failure modes for no gain.

## Decision

- **One repository, one `uv` workspace**, several installable distributions: `optlab-core`, `optlab-native`,
  `optlab-structured`, `optlab-marketdata`, `optlab-risk`, `optlab-server`, under `packages/<name>/src/optlab/<name>`.
- **PEP 420 namespace `optlab`**: no `optlab/__init__.py`; each distribution owns `optlab.<name>`. Imports are
  absolute (`from optlab.core import Market`). The v0 top-level re-exports (`from optlab import black_price`) become
  `optlab.core`'s public API, listed in its `__all__`.
- Each package has its own `pyproject.toml`, minimal dependencies and extras (for example `marketdata[yahoo]`), and its
  tests in `packages/<name>/tests`; the independent references shared by several packages live in a test helper
  package.
- Processes are separated only where their nature differs: `api`, `worker`, `proxy` (ADR-0009).
- Files move with `git mv`, so `git log --follow` keeps their history.

## Validation (spike, A0)

A throwaway workspace with three members (core and structured on hatchling, native on scikit-build-core 1.1.2 with
nanobind) on Python 3.14.7 and uv 0.13.1:

| Check | Result |
|---|---|
| `uv sync` (C++ module built) | 26 s |
| `optlab.__path__` spans the three `src/` folders | yes |
| `pytest --import-mode=importlib`, a `test_basic.py` in every package | 5 passed: same basenames do not clash |
| `optlab-core` installed alone | imports; `optlab.structured` and `optlab.native` absent |
| An engine registered through the entry point group `optlab.engines` | found by `optlab.core` without importing native |
| A C++ `std::invalid_argument` in the bound function | raised as Python `ValueError` |
| pyright (standard) on the pure packages | 0 errors (hatchling writes `.pth` path entries, which pyright reads) |
| pyright on the native package, editable install | the compiled module is invisible (scikit-build-core's redirect hook); with a versioned stub `_ext.pyi` generated by `nanobind_add_stub`: 0 errors |

One trap: MSBuild's file tracker fails on paths above 260 characters (the worktree path alone is 95 characters), so
scikit-build-core's `build-dir` stays short on Windows (its temporary default, or a short absolute folder).

## Implementation (A2)

- Six members under `packages/`, built by hatchling pinned to 1.32.4 (`packages = ["src/optlab"]`), installed editable by
  `uv sync` as `.pth` path entries, which pyright and import-linter read. The lock gained the six members and changed no
  third-party version (938 hashes before and after).
- Tests sit in `packages/<name>/tests`, placed by the highest package they import (a test of the desk that reads the
  lake lives with the server). Their basenames are unique, so pytest keeps its default import mode; the fixtures shared
  by several packages are in `tests/helpers`, on pytest's `pythonpath` and pyright's `extraPaths`, and no test imports
  another test module. The golden recorder stays in `tests/golden`.
- The native member is still the `ctypes` bridge in A2; scikit-build-core and nanobind replace it in A3.

## Consequences

- Package boundaries become real (separate dependency lists, import-linter contracts in CI).
- The CI type-checks the native package without compiling it, thanks to the versioned stub; a test fails when the
  stub drifts from the module.
- Moving every file and rewriting every import is the bulk of A2. The golden numbers guard it bit for bit.

## Alternatives considered

- One distribution with subpackages (v0 shape): no enforced boundary, every user installs duckdb and FastAPI to use
  the closed forms; the Pyodide demo needs `optlab.core` alone.
- Separate repositories: versioning across repos for one maintainer. Rejected.
- Microservices: rejected (context).
