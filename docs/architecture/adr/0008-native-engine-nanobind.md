# ADR-0008: The native engine as a nanobind wheel

- Status: Proposed (A0, 7 November 2026)
- Handoff §1: Moteur natif; §4.5

## Context

`cuda/` (CMake, C++17, CUDA 12.9, `sm_75`) builds a shared library `optlab_cuda_c` with a C API (`capi.cpp`, `capi.h`).
Python loads it with `ctypes` (`gpu.py`, `native.py`) through structures copied field by field from `capi.h`
(`_Request`, `_Result`, `_PathsRequest`, `_LeverageRequest`): a field added on one side and not the other is silent
memory corruption. The library is found in `build/Release/` or `$OPTLAB_CUDA_LIB`. Engine errors are C++ exceptions
turned into error codes, never `exit`, since the engine runs inside the Python process.

## Decision

- `packages/native` builds `cuda/` with **scikit-build-core** and exposes the requests through a **nanobind** module:
  typed arguments, NumPy arrays without copies (`nb::ndarray`), C++ exceptions translated into Python exceptions by
  nanobind. The `ctypes` structures and the C API's error codes go away.
- CMake options kept: `OPTLAB_WITH_CUDA` (OFF builds the CPU engines only), `OPTLAB_CUDA_ARCHS` (`native`,
  `portable`), and the nvcc flags chosen by the ablation (`-prec-div=false -prec-sqrt=false -ftz=true`, no
  `--use_fast_math`, `__expf`/`__logf` off).
- A typed stub (`_ext.pyi`) is generated by `nanobind_add_stub` and versioned; a test compares it with the built
  module. pyright reads the stub, so CI type-checks without compiling (spike, ADR-0003).
- Builds: Windows (MSVC 2022) and Linux (gcc, in the worker image). CI builds the CPU-only wheel on both and runs the
  CPU engine tests; it compiles CUDA without a GPU only if the toolkit installs on a hosted runner without an
  account. GPU tests run on the machine (`optlab check gpu`).
- The fallback to NumPy stays explicit, with its reason, through the engine registry (ADR-0004).
- On Windows the scikit-build-core `build-dir` stays short: MSBuild fails above 260 characters (spike).

## Consequences

- Prices are unchanged: the same C++ code runs; only the binding changes. Golden numbers (CPU and GPU) and times
  within 5 % are the exit criteria of A3.
- `pip install optlab-native` is a normal wheel; no DLL to find by path.
- nanobind and scikit-build-core become build dependencies of `optlab-native` only.

## Alternatives considered

- **Keep ctypes**: no build step in Python, but the duplicated structures are the main reliability risk of the
  bridge.
- **pybind11**: mature, larger binaries and slower compile; nanobind is its successor by the same author, with
  first-class ndarray support and stub generation.
- **Cython or cffi**: still a hand-written mirror of the C structures.
